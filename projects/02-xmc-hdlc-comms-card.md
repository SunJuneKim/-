# 프로젝트 2: XMC HDLC 통신카드 (자체 통신카드 대체)

## 개요

| 항목 | 내용 |
|------|------|
| **기간** | 2025.10 ~ 현재 |
| **역할** | Linux 드라이버 호환·통신 검증 |
| **인원** | 2명 |
| **목적** | 기존 **상용 통신카드**를 **자체 개발 FPGA 통신카드**로 대체 |

---

## 배경

- SBC CPU + **상용 통신카드** 환경에서 동작하던 기존 SW 스택 존재
- 기존 드라이버: **tdrv009**, **tdrv002** (상용)
- 자체 개발 카드(FPGA)로 교체하면서 **유저 애플리케이션 수정 없이** 통신 유지 필요

---

## 담당 업무

### 1. 호환 레이어 개발
- 상용 드라이버 **매뉴얼** 분석 — 기능·레지스터 맵 파악
- 자체 FPGA 카드 **매뉴얼** 대조 — 기능 유무·차이점 식별
- **호환 레이어(compatibility layer)** 구현 → 기존 유저 앱 **무수정** 동작 목표

### 2. 통신 구성

| 채널 | 프로토콜 | 비고 |
|------|----------|------|
| 7채널 | RS422 | |
| 1채널 | HDLC | |
| **합계** | **8채널** | 다중 채널 동시 요청 처리 진행 중 |

### 3. 테스트·검증
- **PC ↔ 장비** 통신
- PC측 통신 프로그램 요구사항에 맞춘 **목업(mock)** 사전 테스트
- 테스트 스펙 변경 대응:
  - 초기 → **HDLC 50byte 200Hz**, **RS422 200byte 1Hz** (재협의 후 반영)

### 4. 플랫폼 이슈 대응
- 임의 지정 **포트 변경** 요청
- **디바이스 노드명** 수정 및 **SCC 리맵핑**

---

## 현재 이슈 (진행 중)

| 이슈 | 상태 | 분석 |
|------|------|------|
| HDLC **배치(batch) 현상** | 디버깅 중 | |
| HDLC **미정렬** | 디버깅 중 | |
| 자체 유저 프로그램 + PC 프로그램 | **정상** | |
| 변경 불가 **업체 레거시 유저 프로그램** | **문제 발생** | **stash/split 미구현** 추정 |

> HDLC 프레이밍: 일부 스택은 큰 프레임을 stash/split으로 나누어 처리 — 레거시 앱이 기대하는 동작과 불일치 가능

## 이력서에 넣을 이슈 선별 (요청 반영)

| 이슈 | 이력서 포함 | 이유 |
|------|-------------|------|
| 상용→자체 호환 레이어 | ✅ 필수 | AD Framework abstraction과 동형 |
| 8채널 RS422/HDLC | ✅ 필수 | 다채널 실시간 |
| 레지스터 맵·매뉴얼 대조 | ✅ | 임베디드 역량 |
| HDLC 50B@200Hz, RS422 200B@1Hz | ✅ | 정량 요구사항 |
| 포트/노드명/SCC 리맵 | △ 간략 | 플랫폼 포팅 능력 |
| PC 목업 테스트 | ✅ | 검증 주도 |
| stash/split 디버깅 | ✅ | **현재 진행 + 기술 깊이** |
| 업체 레거시 앱 black-box 호환 | ✅ | 차별화 스토리 |

## 42dot 이력서용 bullet (초안)

- 상용 통신카드(tdrv009/002) → **자체 FPGA 카드** 대체를 위한 **Linux 드라이버 호환 레이어** 개발
- 상용·자체 **레지스터 맵 대조** 및 API 호환으로 **레거시 유저 앱 무수정** 통신 달성 (자체 앱 기준)
- **RS422 7채널 + HDLC 1채널** (8ch) 다중 통신, **HDLC 50B@200Hz / RS422 200B@1Hz** 요구사항 대응
- PC 연동 **목업 테스트** 선행으로 요구사항 변경 사이클 단축
- 레거시 업체 SW 호환 이슈: **HDLC stash/split** 프레이밍 분석·디버깅 진행 중
