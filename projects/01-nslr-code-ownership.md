## 1. 담당 범위 한 장 요약 (면접·이력서용)


## 3. 스케줄러 — 사수 역할 어필 (경력직 차별화)

동료가 만든 모듈을 **숨기지 말고**, 경력직다운 **리드 경험**으로 씁니다.

### 이력서 bullet (택 1)

- 관측 **스케줄러** 모듈: 동료 개발, 본인이 **운영제어부 아키텍처·구성품 인터페이스·통합 기준** 가이드(사수) 및 연동 검증
- **스케줄러–시스템 로직** 경계 설계: 스케줄러 팀에 API·타이밍·상태머신 요구사항 정의, **통합 후 현장 관측**까지 기술 리드

### 면접 한 줄

> "스케줄러 코드는 제가 짜지 않았지만, **전체 시스템 맥락에서 어떻게 붙어야 하는지** 제가 정의했고, 동료가 그 안에서 구현했습니다. 통합·현장 이슈는 제가 받았습니다."

→ 42dot AD에서 **cross-functional lead**, **middleware integration** 스토리와 동형

## 4. "일만 열심히" → 경력직 어필 변환법

많은 분이 **작업 목록**만 쓰고, 채용담당자는 **오너십·임팩트·규모**를 봅니다.

### ❌ 약한 표현
- "우주물체 프로젝트 참여"
- "C#, OpenCV 사용"
- "현장 근무"
- "여러 구성품 연동"

### ✅ 강한 표현 (공식)

| 약한 말 | 강한 말 (템플릿) |
|---------|------------------|
| 참여했다 | **운영제어부 시스템 로직 단독 오너** (스케줄러 제외) |
| 연동했다 | **7구성품·3카메라 실시간 통합** 설계·구현 |
| 현장 갔다 | **구현·실장비 디버깅·관측 운영** 2년 병행 |
| 튜닝했다 | **50 arcsec 이하** 정밀도 기여 (시간동기화·별보정) |
| 가르쳤다 | 스케줄러 모듈 **기술 리드(사수)** — 인터페이스·통합 가이드 |
| 고생했다 | **아키텍처 고정** 하 timing jitter **구조적 분석** 후 튜닝으로 운영 안정화 |

### 3문장 공식 (프로젝트당)

1. **무엇을** 맡았는가 (범위·오너십)  
2. **어떤 제약** 아래서 (ns 동기화, 현장, 다업체)  
3. **무엇이** 달라졌는가 (50 arcsec, 3년 무중단 운영, 관측 성공 등)

**예시:**
> 차세대 SLR(NSLR) 운영제어부 **시스템 로직 전반을 단독** 설계·구현했습니다. NTP/GPS 기반 ns급 동기화와 7구성품 통합 제약 하에서 별보정·트래킹 로직을 구축했고, **50 arcsec 이하** 관측 정밀도 달성에 기여했습니다. 관측 스케줄러는 동료 개발에 **사수**로 인터페이스·통합을 리드했습니다.
