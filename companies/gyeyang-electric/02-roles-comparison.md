## 1. SW 설계 엔지니어

### 하는 일
| 영역 | 내용 |
|------|------|
| **임베디드 SW** | MCU 기반 ECU 응용·저수준 SW (C) |
| **MBD** | Simulink 등 **모델 기반** 제어 SW (모터 제어 알고리즘) |
| **BSW** | **Mobilion** 등 AUTOSAR Classic **기본 SW** 설정·통합·CDD |

→ 모터 ECU에서 **실제로 돌아가는 SW를 만드는** 직무

### 본인 적합도: ★★★★☆ (1순위)

| 맞는 점 | 안 맞는 점 |
|---------|------------|
| Linux C **드라이버 modify** | **AUTOSAR BSW** 실무 없음 |
| **호환 레이어** = CDD/추상화 사고 유사 | **MBD/Simulink** 없음 |
| **7구성품 실시간 통합** | **CAN/LIN** 직접 경험 부족 |
| **20ms 제어 루프**, ns 타이밍 | **모터 제어** 도메인 신규 |
| Yocto, 펌웨어 기반 | ASPICE 프로세스 경험 없음 |
| 응용 SW (C#) → ASW/도구로 전환 가능 | |

**결론:** 로우레벨~응용까지 하고 싶다는 본인 방향과 **가장 일치**. 갭은 있지만 **경력 7년 + 통합·드라이버**로 입사 후 학습 가능한 구조.

## 2. 시스템 설계 엔지니어

### 하는 일
- OEM(현대차 등) **요구사양** 분석·내부 요구로 변환
- **시스템 상세 설계** (블록 다이어그램, 인터페이스, 상태머신)
- **고장 분석** (FMEA, FTA 등 안전·신뢰성)
- **변경·이슈 관리** (ASPICE traceability)

### 본인 적합도: ★★★☆☆ (2순위, 기피 타당)

| 맞는 점 | 안 맞는 점 |
|---------|------------|
| NSLR **7모듈 통합 아키텍처** 이해 | **문서·회의 비중** 높음 |
| 스케줄러 **사수** = 인터페이스 정의 | 코딩 비중 **낮음** |
| timing trade-off 분석 경험 | FMEA/FTA **공식 방법론** 없음 |
| 다업체 협업 (한화) | OEM 요구 분석 **자동차 프로세스** 미경험 |

### 🔴 반론: "문서만 한다" — **반만 맞음**

**맞는 부분**
- ASPICE 환경에서는 **SRS, SyRS, 설계서, 추적 매트릭스**가 일상
- 코딩보다 **스펙·안전 분석** 비중이 큼 → 본인 성향과 **어긋날 수 있음**

**틀린 부분**
- "문서 작성자"가 아니라 **시스템 아키텍트**에 가까운 경우 많음
- 고장 분석은 **HW+SW+제어** 이해 없이 못 함 — 본인 **시스템 오차 구조 분석** 경험과 연결 가능
- NSLR에서 **인터페이스·타이밍 정의(사수)** 한 것 = 시스템 설계의 축소판

**그래도 SW 설계를 추천하는 이유**
- 본인은 **만들고 디버깅하는** 에너지가 강함 → 설계 직무가 **만족도** 높음
- 시스템 설계는 **나중에 5~10년차**에 가면 자연스럽게 열림 (지금 굳이 X)

## 3. SW 검증 엔지니어

### 하는 일
- **단위 테스트** (함수/모듈)
- **통합 테스트** (SWC, ECU, 차량)
- 동적 검증, 회귀, (환경에 따라 HIL, 커버리지)

### 본인 적합도: ★★★☆☆ (역량은 있으나 **지원 비추천**)

| 맞는 점 | 안 맞는 점 |
|---------|------------|
| **현장 통합·디버깅** 3년 | 본인 **개발 오너십** 낭비 |
| 실장비 연동 검증 | 7년차 **성장 천장** 우려 (본인 판단 타당) |
| Python/C# 테스트 도구 | |

### 🔴 반론: "진입장벽 낮다" — **반은 틀림**

**틀린 부분 (자동차 SW 검증)**
- 단순 QA가 아님: **ASPICE**, **ISO 26262** 검증, **MC/DC 커버리지**, **HIL** 세팅
- 모터 ECU **안전 관련** SW 검증은 책임 무거움
- "아무나 한다" 수준 **아님** — 다만 **개발자로서의 진입**은 상대적으로 쉬울 수 있음

**맞는 부분 (본인 커리어 관점)**
- 7년차가 **검증만** 하면 연봉·성장에서 **설계 대비 불리**한 경우 많음
- 본인 강점(드라이버, 통합, 시스템 로직) **활용도 낮음**
- "안 하겠다"는 판단 → **동의**. 다만 **면접/이력서**에서 "검증 경험"은 **자산**으로 언급
