## 본문 (제출용 · 4단 구성)

### 1. Embedded 개발자로 성장한 과정

상용 통신카드를 FPGA 카드로 갈아끼되, 기존 Application은 한 줄도 수정할 수 없는 조건에서 RS422 7채널과 HDLC 1채널을 동시에 받아 70시간 넘게 안정적으로 돌린 뒤 납품한 경험이, 제가 일하는 방식을 가장 잘 보여 줍니다. HW와 SW 사이를 맞추고, 깨지기 쉬운 인터페이스를 끝까지 붙여 놓는 일이 제 일입니다.

그 전에도 방향은 같았습니다. 에너시스에서 STM32·MSP430 기반 전자카드 펌웨어를 만들며 SPI, UART, I2C, RS485, ADC로 HW Interface를 익혔고, 4–20mA Calibration과 EMI 인증, ATE 자동화까지 하드웨어와 맞물린 개발을 해 왔습니다. 신보에서는 Linux Device Driver, FPGA 통신카드, 다수 장비를 실시간으로 묶는 운영제어 시스템, Yocto 기반 Embedded Linux까지 범위를 넓혔습니다. 한 가지 스택에만 머물지 않고, 프로젝트가 요구하는 계층까지 내려가거나 올라가며 Embedded 전반을 이어 온 7년입니다.

### 2. 가장 어려웠던 프로젝트 — IRST FPGA 통신카드

IRST 프로젝트는 기존 Application을 전혀 수정할 수 없는 환경에서, 자체 FPGA 카드가 상용 통신카드와 동일하게 동작해야 했습니다. 상용 카드와 FPGA 카드의 Register Map과 Driver를 대조해 호환 Layer를 설계했고, FIFO를 순환 Queue로 바꿔 수신 구조를 정리했습니다. HDLC Zero-length Packet과 RS422 Split RX 이슈는 Application을 건드리지 못하는 조건에서 Driver 쪽에서 흡수해야 했고, 헤더 기반 패킷 파싱으로 기존 바이너리가 수정 없이 돌아가게 맞췄습니다.

검증은 HIL 환경과 Python·C# 테스트 프로그램을 직접 만들어 진행했습니다. 1차 납품 뒤 고객 Application 쪽 다채널 절차가 부족하다는 변경이 들어왔을 때도 Driver 구조를 다시 정리해 2차 납품까지 마쳤습니다. 이 프로젝트를 통해 Driver는 코드 몇 줄의 문제가 아니라, HW와 Application 사이 인터페이스를 설계하고 여러 환경에서도 깨지지 않게 만드는 일이라는 걸 몸으로 배웠습니다.

### 3. 문제를 끝까지 해결하는 방식

저는 문제의 원인이 어디에 있는지부터 보는 편입니다. NSLR에서는 7개 장비를 실시간으로 묶는 운영제어 시스템을 맡았고, NTP/GPS 시간 동기화, UDP/TCP 통신, Event Timer, Closed-loop Calibration을 구현했습니다. 현장에 상주하며 실장비와 맞춰 보니 Timing Jitter가 정밀도에 바로 닿는 경우가 많았고, 구조를 크게 바꿀 수 없을 때는 Python 분석 도구를 직접 만들어 측정·튜닝으로 풀었습니다. 새 기술을 빠르게 익혀 실제 제품에 붙이는 쪽이 강점입니다.

개발만 해 온 것은 아닙니다. 아트랩소프트에서 원자력 ESF-CCS 계통 SW 검증을 수행하며 IEEE 기준으로 요구사항에서 시험 케이스, 단위·통합·시스템 시험, 증적까지 이어지는 프로세스를 익혔습니다. 타 계통과 맞물리는 PLC 모듈 통합시험도 담당했고, Rev-up 소스 검토 자동화로 검증 팀의 반복 공수를 줄인 경험도 있습니다. 원자력과 자동차는 도메인이 다르지만, 안전과 직결된 SW를 표준과 요구사항에 맞게 검증하고 기록하는 일이라는 점은 같습니다. 계양전기가 ISO 26262를 따르는 환경이라면, 처음부터 낯선 프로세스가 아니라 익숙한 방식으로 빠르게 적응할 수 있다고 봅니다.

### 4. 계양전기에서 기여하고 싶은 점

계양전기는 다양한 Embedded Platform과 BSW 기술을 바탕으로 모터 ECU 제품을 만드는 회사로 알고 있습니다. 저는 MCU Firmware부터 Linux Device Driver, FPGA Interface, 실시간 통신, HW-SW Integration, HIL·실장비 검증까지 이어지는 경험을 가지고 있습니다. Mobilgene AUTOSAR와 MBD는 입사 후 더 깊이 배울 영역이지만, 새 HW 환경에서 인터페이스를 빠르게 읽고 Driver와 BSW를 안정적으로 구현하는 일은 지금까지 해 온 일과 같습니다.

문제가 생기면 로그와 현상부터 좁혀 가며, Application을 건드릴 수 없을 때는 Driver와 통합 시험 쪽에서 해결책을 찾는 방식으로 일해 왔습니다. 계양전기에서도 HW와 SW를 연결하는 Embedded 개발자로서 제품 안정성과 품질 향상에 기여하겠습니다.

## 압축본 (항목별 1문단 · 사이트 항목 나눌 때)

### 지원동기·성장 배경 (약 600자)

상용 통신카드를 FPGA 카드로 교체하되 Application은 수정할 수 없는 조건에서, RS422 7채널·HDLC 1채널 동시 통신을 70시간 이상 검증해 납품한 IRST 프로젝트가 제 역량을 가장 잘 보여 줍니다. STM32 펌웨어와 Calibration에서 출발해 Linux Driver, FPGA 통신카드, 다수 장비 실시간 통합, Embedded Linux까지 Embedded 전 계층을 이어 온 7년입니다. HW Interface를 읽고, 깨지기 쉬운 경계를 설계하고, 실장비에서 끝까지 확인하는 개발자입니다.

### 직무 역량·프로젝트 경험 (약 700자)

IRST에서는 Register Map 분석, 호환 Layer 설계, FIFO→순환 Queue 개선, HDLC Zero-length·RS422 Split RX 처리로 기존 Application 무수정 호환을 구현했습니다. HIL과 Python·C# 테스트 앱으로 검증했고, 요구사항 변경에도 Driver 구조를 개선해 납품을 완료했습니다. NSLR에서는 NTP/GPS 동기화, Event Timer, Closed-loop Calibration, 7개 장비 실시간 연동을 담당했고, 현장에서 Timing Jitter를 분석·튜닝했습니다. ESF-CCS 검증에서는 IEEE 기반 UT/IT·PLC 모듈 통합시험을 수행하며 고신뢰 SW의 요구사항-시험-증적 프로세스를 익혔습니다.

### 입사 후 포부 (약 400자)

계양전기의 Mobilgene AUTOSAR·MBD 환경을 빠르게 학습하며, 통신·Driver·통합 시험에 즉시 기여하겠습니다. ISO 26262는 도메인은 다르지만 ESF-CCS에서 익힌 안전 SW 검증 방식과 맞닿아 있어, 표준과 프로세스 적응에 자신이 있습니다. MCU부터 Driver, 실장비 검증까지 이어지는 경험으로 모터 ECU 제품의 안정성과 품질 향상에 기여하겠습니다.
