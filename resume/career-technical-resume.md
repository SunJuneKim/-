## 2. 경력 요약

Linux **디바이스 드라이버**·**실시간 통합 운영 SW**를 중심으로 7년 이상 개발해 온 선임 연구원입니다.  
에너시스에서 **STM32 MCU 보드·보정·ATE 자동화**로 시작했고, 아트랩소프트에서 **SW 검증**을 거쳐, 현재 신보에서는 **NSLR(레이저 거리측정) 운영제어**와 **IRST(통신카드·드라이버)** 를 담당했습니다.

**강점:** 맨땅 과제에서 논문·매뉴얼 찾아 직접 맞춰 가는 자기주도, 앱을 못 고치는 조건에서 **드라이버로 문제를 끝내는** 실무, 다수 구성품 **통합·현장 연동**.

**일정별 수행 내용**

| 시기 | 내용 |
|------|------|
| **2026.01 – 02월 말** | 기존 상용 드라이버 SW 숙지, 상용·자체 **레지스터 맵핑** 대조 |
| **2026.03 중순** | 통신카드 제작 완료 → 사내 베이스보드 장착 |
| **2026.03** | **HIL 테스트** — 드라이버 인식, HW 제어, 맵핑, 통신 확인 |
| **1차 납품** | 초기 절차서 기준 납품 |
| **이후 – 06** | 업체로부터 **애플리케이션 사용 스펙** 수령 → 초기와 상이, **요구조건 변경**에 따른 재작업 |

**요구사항 변경 이슈 (경력기술서용 서술)**

- 초기: "기존 **절차서**대로 진행하면 된다"는 안내
- 실제: 절차서에 **다중 채널 동시 통신 절차 없음**
- 변경: **8채널(RS422 7 + HDLC 1) 동시 통신**, 채널별 **통신 주기 상이**
- 업체 스펙 전달이 지연·불명확하여 **재진행** — 중간 **1차 납품** 및 약 **2개월 공백** 후 6월까지 수정·재납품 진행

**기술 상세**

- **RS422 7ch:** 기존 tty 방식 → **tty** 채용
- **HDLC 1ch:** **ioctl**
- 드라이버: **FIFO → 원형 큐(circular queue)** 전환
- **이슈:** HDLC 간헐적 **0 byte** 수신 / RS422 **데이터 분할 수신**
- 상위 **앱 수정 불가** → 드라이버에서 **헤더 조건문 기반 패킷 파싱**으로 처리 (비정석이나 실장비 대응)
- **70시간 이상 연속 가동** 안정성 확인 후 납품

**성과**

- 자체 FPGA 통신카드 **호환 레이어·드라이버·검증 앱** 구축 및 **납품**
- 요구사항 변경(다중 채널·주기) 및 스펙 지연 상황에서 **재설계·재검증** 완료

#### [프로젝트 2] NSLR — 차세대 우주물체 레이저 거리측정(SLR) 운영제어

| 항목 | 내용 |
|------|------|
| **기간** | **2023.01 – 2025.10** (약 2년 10개월) |
| **역할** | 운영제어부 **시스템 로직 오너** (Scheduler 제외) / Scheduler **사수** |
| **개요** | 우주물체·위성 지향 후 레이저 발사·**거리 측정**. 지상보정(시스템 딜레이), 별보정(마운트·광학) 연동 |

**주요 업무**

- 7개 구성품(이벤트타이머, 광전자, 레이저, 마운트, 항공탐지, 대기환경, 타과제 외부망) + 카메라 3종 **제어·동기화**
- **NTP/GPS** 기반 시간 동기화, 이벤트 타이머, 위성/우주물체 지향 관측 시퀀스
- **별보정** 운용·로직, 지상보정 연동
- 운영 UI(C#, WinForms), Python/PostgreSQL 데이터 분석, 외부 .dll 통합
- **Scheduler 모듈:** 동료 개발, 본인 **인터페이스·타이밍·통합 가이드(사수)**
- 거창 현장 **TRR** — 개발·실장비 연동·관측 **병행** (유지보수만 아님)

**과제 특성**

- 시스템 설계 초안 단계 과제 — 논문·자료 조사하며 **운영제어부부터 맞춰 감**
- ns급 정밀도 요구 환경에서 **타이밍 jitter** 등 시스템 전반 이슈 인지·담당 범위 내 튜닝

**성과**

- **TRR** 진행, 시스템 납품·상용화 기여
- **선임연구원** 승진
- 운영제어부 담당 범위(스케줄러·마운트 엔코더 정밀 서브루프 제외) **단독 수행**
